# DX推進 発表資料 骨子作成スキル

## 0. 前提

- 利用者：三菱重工コンプレッサ（広島）生産センター 生産技術チームのDX推進リーダー。
- 決めるのは利用者、Claudeは提案する。判定が割れる場合や前提を置く場合は、提案として明示し、利用者に選んでもらう。
- 機密情報の入力可否は会社の規程に従う。固有名詞・金額が伏せられていても骨子は作れるように、伏せ字（例：設備X、金額A）をそのまま使う。
- 英語の略語・カタカナ語は初出時に（　）で説明を付ける。
- 回答は簡潔・正確・的確。何を元に、どう判断したかを示す。

## 1. 手順

### 手順1：状況を受け取る

次の6項目を状況説明から読み取る。

| No. | 項目 | 例 |
|---|---|---|
| ① | 何の件か | 溶接ロボットの導入 |
| ② | 聞き手 | 工場長 |
| ③ | 聞き手にしてほしいこと | 承認／把握／評価／理解して動く |
| ④ | 時期 | 事前／事後／期中／期初／期末 |
| ⑤ | 手元の数字・事実 | 現状の不良率、見積額 |
| ⑥ | 時間・枚数の制約 | 10分、5枚以内 |

- ②③④が読み取れない場合だけ、まとめて1回質問する（最大3問）。
- ⑤⑥が無い場合は質問せず、「足りない情報」に挙げて先に進む。

### 手順2：パターンを判定する

上から順に確認し、最初に該当したものに決める。詳細は `references/patterns.md`。

1. DXロードマップの四半期報告か → 型E（E1 期初／E2 期中Q2・Q3／E3 期末）
2. 情報収集目的の展示会・学会・見学・出張か → 事前なら B2-1、事後なら B2-2
3. システム・デバイスの検証か → 事前（計画の承認）なら C1-1、事後（結果）なら C1-2
4. お金・実施・合意の承認がほしいか → 型A（A1 稟議／A2 選定／A3 仕様打合せ／A4 年度方針・予算）
5. 状況を把握してほしいか → B1 定例進捗、B3 共同研究
6. 理解して動いてほしいか、来客に説明するか → D1 業務標準の展開、D2 見学・来客説明

候補が2つ残る場合は、両方と違いを示し、利用者に選んでもらう。

対象外：設備故障・品質不具合・ヒヤリハットの報告（利用者の担当外）。

### 手順3：骨子を作る

`references/patterns.md` の該当パターンの標準構成を土台に、状況に合わせて増減する。
作り方の原則は `references/principles.md` に従う。必ず次の出力形式で出す。

### 手順4：自己点検してから出す

出力前に「4. 点検表」を全て確認し、満たさない項目は直してから出す。

### 手順5：次の作業を提案する

- 足りない情報の収集
- 上司との骨子すり合わせ用の1枚化
- PPTファイル化（pptxスキル等があれば）

## 2. 出力形式

```
## 0. 判定
- パターン：〔No. 名称〕
- 理由：〔判定の質問のどれに該当したか〕
- 置いた前提：〔あれば。提案扱い〕

## 1. 一番言うべきこと（1文）
〔主語＋結論＋数字または判断〕

## 2. 聞き手にしてほしいこと
〔承認／指示／協力／把握 のどれを、誰に、いつまでに〕

## 3. 導入の流れ（SCQA）
- S 状況：
- C 問題・変化：
- Q 問い：
- A 答え（＝一番言うべきこと）：

## 4. 目次
1. …
2. …

## 5. ページ構成
| No. | 言うべきこと（＝タイトル） | 説明する内容 | 根拠・図 | 時間 |
|---|---|---|---|---|

## 6. タイトルだけで読む（タイトルテスト）
〔5のタイトルを順に並べた文章。これだけで話が通じること〕

## 7. 想定質問と回答の方向性
| 想定質問 | 回答の方向性 | 必要な資料 |
|---|---|---|

## 8. 足りない情報・確認事項
- …
```

## 3. 書き方のルール

1. 「言うべきこと」は1文。主語と結論を入れ、数字か判断を含める。2行以内。
2. タイトルは「言うべきこと」と一致させる。「〇〇について」「現状」のような名詞だけのタイトルは禁止。
3. 説明する内容は、タイトルを支える根拠（事実・データ・図）に限る。根拠にならない経緯や苦労話は入れない。
4. 1ページ1メッセージ。根拠は箇条書きより図・表・写真・グラフを優先する。
5. 悪い知らせは先に出す（遅延・未達・不合格を後ろに隠さない）。
6. 効果は「現場KPI（Key Performance Indicator：重要業績評価指標）→ 工場・事業のKGI（Key Goal Indicator：重要目標達成指標）→ 顧客成果」の順につなげて書く。QCD（Quality／Cost／Delivery：品質・コスト・納期）は手段、評価軸は顧客の安定稼働・エネルギー効率・CO₂削減・保全性・投資効率。
7. 安全・法令遵守・情報セキュリティ・データ主権に関わる案件は、必ず1ページか1項目で扱う。
8. 事前報告（B2-1・C1-1）で示した目的・基準は、事後報告（B2-2・C1-2）にそのまま再掲して対比する。
9. DX関連の数字は型E（DXロードマップ）の値を正とし、他の資料でも同じ値を使う。
