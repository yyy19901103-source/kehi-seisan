# DX推進 発表資料 骨子作成スキル

## 0. 前提

- 利用者：三菱重工コンプレッサ（広島）生産センター 生産技術チームのDX推進リーダー。
- 決めるのは利用者、Claudeは提案する。判定が割れる場合や前提を置く場合は「提案」と明示し、利用者に選んでもらう。
- 機密情報の入力可否は会社の規程に従う。伏せ字（例：設備X、金額A）のままでも骨子を作る。
- 英語の略語・カタカナ語は初出時に（　）で説明を付ける。
- 回答は簡潔・正確・的確。何を元に、どう判断したかを示す。
- このスキルが作るのは骨子（考える部分）まで。デザインやPPTファイル化は次の工程。

## 1. 手順

### 手順1：状況を受け取る

状況説明から次の7項目を読み取る。

| No. | 項目 | 例 |
|---|---|---|
| ① | 何の件か | 溶接ロボットの導入 |
| ② | 聞き手（役職・その件への関心と知識） | 工場長。費用に厳しい、技術は詳しくない |
| ③ | 聞き手にしてほしいこと | 承認／把握／評価／理解して動く |
| ④ | 時期 | 事前／事後／期中／期初／期末 |
| ⑤ | 手元の数字・事実 | 現状の手直し費用、見積額 |
| ⑥ | 時間・枚数の制約 | 15分、10枚以内 |
| ⑦ | 資料の使われ方 | 投影して話す／事前配布して読ませる／配布のみ |

- ②③④が読み取れない場合だけ、まとめて1回質問する（最大3問）。
- ⑤⑥⑦が無い場合は質問せず、⑦は「投影して話す」と置いて進め、「足りない情報」に挙げる。

### 手順2：パターンを判定する

上から順に確認し、最初に該当したものに決める。詳細は `references/patterns.md`。

1. DXロードマップの四半期報告か → 型E（E1 期初／E2 期中Q2・Q3／E3 期末）
2. 情報収集目的の展示会・学会・見学・出張か → 事前なら B2-1、事後なら B2-2
3. システム・デバイスの検証か → 事前（計画の承認）なら C1-1、事後（結果）なら C1-2
4. お金・実施・合意の承認がほしいか → 型A（A1 稟議／A2 選定／A3 仕様打合せ／A4 年度方針・予算）
5. 状況を把握してほしいか → B1 定例進捗、B3 共同研究
6. 理解して動いてほしいか、来客に説明するか → D1 業務標準の展開、D2 見学・来客説明

候補が2つ残る場合は、両方と違いを示し、利用者に選んでもらう。
対象外：設備故障・品質不具合・ヒヤリハットの報告（利用者の担当外）。

### 手順3：骨子を作る

1. 一番言うべきことを1文で決める（ピラミッドの頂点）。
2. それを支える根拠を2〜4個に分ける（重複なし・漏れなし）。
3. `references/patterns.md` の標準構成を土台に、根拠を各ページに割り当てる。
4. タイトルだけを並べて読み、話が通るまで直す（横の論理）。
5. 各ページの根拠がタイトルを証明しているか確かめる（縦の論理）。

作り方の原則は `references/principles.md`、出力の見本は `references/example.md` を参照する。

### 手順4：点検してから出す

「4. 点検表」を全て確認し、満たさない項目は直してから出す。

### 手順5：利用者の確認を待つ

骨子を出したら止まり、利用者の修正を受ける。修正後に次を提案する。

- 足りない情報の収集方法
- 上司との事前すり合わせ用の1枚（一番言うべきこと＋タイトル一覧）
- PPT化（Claude for PowerPoint で会社のテンプレートに流し込む、または pptx スキル）

## 1. 一番言うべきこと（1文）
〔主語＋結論＋数字または判断〕

## 2. 聞き手にしてほしいこと

## 3. 導入の流れ（SCQA）

- C 問題・変化：

## 4. 目次

## 5. ページ構成

## 3. 書き方のルール

### 全体
1. 一番言うべきことは1文。主語と結論を入れ、数字か判断を含める。
2. 冒頭で結論、最後に結論と依頼事項を再掲する。最終ページは結論・依頼事項のまま質疑に入る（「ご清聴ありがとうございました」で終えない）。
3. 現状とあるべき姿の差を示し、その差を埋める案として提案する。
4. 悪い知らせは先に出す（遅延・未達・不合格を後ろに隠さない）。
5. 詳細データ・想定質問への回答は付録に回し、本編は時間内に収める。

### ページ
6. タイトルは「言うべきこと」を文章で書く。2行以内。「〇〇について」「現状」など名詞だけは禁止。
7. 1ページ1メッセージ。根拠は3点以内。
8. 根拠は箇条書きより図・表・写真・グラフを優先し、結果を示すページは図を1つに絞る。図の中に言いたい点を書き込む。
9. 図には出典・期間・件数を付ける。平均値だけでなくばらつき（σ、Cp/Cpk など）を示す。

### 中身
10. 効果は「現場KPI（Key Performance Indicator：重要業績評価指標）→ 工場KGI（Key Goal Indicator：重要目標達成指標）→ 顧客成果 → 事業」の順につなげる。QCD（Quality／Cost／Delivery：品質・コスト・納期）は手段、評価軸は顧客の安定稼働・エネルギー効率・CO₂削減・保全性・投資効率。
11. 安全・法令遵守・情報セキュリティ・データ主権に関わる案件は、必ず1ページか1項目で扱う。
12. 事前報告（B2-1・C1-1）で示した目的・基準は、事後報告（B2-2・C1-2）にそのまま再掲して対比する。
13. DX関連の数字は型E（DXロードマップ）の値を正とし、他の資料でも同じ値を使う。

### 言葉
14. 数字のない抽象語だけの文を書かない。禁止例：「推進する」「強化する」「最適化する」「効率化を図る」「包括的な」「シナジー」「DXを加速」。使うなら何をどれだけ変えるかを数字で書く。
15. 根拠を毎回きれいに3つ揃えない。実際の根拠の数に合わせる。
16. 「その人が上司に向かって口に出して言うか」で表現を確かめる。

## 4. 点検表

横の論理（ページのつながり）
- [ ] タイトルだけを順に読んで、話が通じる
- [ ] 一番言うべきことと、全タイトルが矛盾しない
- [ ] 根拠の分け方に重複・漏れがない

縦の論理（各ページの中身）
- [ ] 各ページの図・データがタイトルを証明している
- [ ] 根拠は3点以内、図には出典・期間・件数がある

聞き手と場面
- [ ] 聞き手にしてほしいことが明記されている
- [ ] 型Aは1ページ目に結論と依頼事項がある
- [ ] 時間・枚数の制約に収まっている（超える分は付録）
- [ ] 資料の使われ方（投影／事前配布）に合った文字量になっている
- [ ] 想定質問に「費用」「リスク」「やらない場合」が入っている（型Aの場合）

前提
- [ ] 安全・法令・セキュリティ・データ主権の要否を確認した
- [ ] 抽象語だけの文がない
- [ ] 略語・カタカナに説明を付けた
